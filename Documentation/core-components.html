Core Components

Understanding the Framework Architecture

Architecture Overview

BICurlDownloader is built on a modular architecture with clearly separated concerns. Each component has a specific responsibility and communicates with other components through well-defined interfaces.

Core Layer

Download management, task coordination, and cURL integration

Background Layer

Silent audio generation and audio session management

Network Layer

Server capabilities detection and network monitoring

Storage Layer

File operations and state persistence

BIDownloadManager

The central coordinator for all download operations. This singleton class manages the download queue, task lifecycle, and resource allocation.

Responsibilities

  • Managing the global download queue
  • Enforcing concurrent download limits
  • Coordinating background audio activation
  • Providing task lookup and filtering
  • Broadcasting state changes via notifications

Key Features

// Singleton access
let manager = BIDownloadManager.shared

// Configure global settings
var config = BIDownloadManagerConfiguration()
config.maxConcurrentDownloads = 3
config.enableLogging = true
manager.configure(config)

// Create and manage tasks
let task = manager.download(url: url, destinationPath: path)

// Query tasks
let activeTasks = manager.getActiveTasks()
let queuedTasks = manager.getQueuedTasks()

// Bulk operations
manager.pauseAll()
manager.resumeAll()
manager.cancelAll()

Task Queue Management

The manager maintains two internal collections:

  • Active Tasks - Currently downloading (up to maxConcurrentDownloads)
  • Task Queue - Waiting tasks that will start when slots become available

When a task completes, fails, or is paused, the manager automatically starts the next queued task.

BIDownloadTask

Represents an individual download operation. Each task encapsulates the download URL, destination, options, and current state.

Task Lifecycle

  1. Creation - Task is created via BIDownloadManager
  2. Pending - Task is queued and waiting to start
  3. Server Check - Capabilities are validated (Range support, content length)
  4. Downloading - Active download with progress updates
  5. Terminal States - Completed, Failed, or Cancelled

State Transitions

pending → downloading → completed
        ↓               ↓
        ↓               → paused → downloading
        ↓               ↓
        → cancelled     → failed
                        ↓
                        → cancelled

Properties and Methods

// Properties
task.id              // Unique identifier
task.url             // Download URL
task.state           // Current state
task.progress        // Progress object
task.note            // Custom tag/label

// Control methods
task.pause()         // Pause download
task.resume()        // Resume download
task.cancel()        // Cancel download

// Delegate
task.delegate = self // Set delegate for callbacks

Progress Tracking

Each task provides a standard Foundation Progress object:

let progress = task.progress
print("Downloaded: \(progress.completedUnitCount) bytes")
print("Total: \(progress.totalUnitCount) bytes")
print("Percentage: \(progress.fractionCompleted * 100)%")

BIMultipartDownloader

Internal component that handles the actual download logic, including multipart splitting and parallel chunk downloads.

Download Strategy Selection

The downloader automatically chooses between single-threaded and multipart downloads based on:

  • Server support for Range requests (Accept-Ranges header)
  • Known content length (Content-Length header)
  • File size threshold (minimum 5 MB for multipart)
  • User configuration (enableMultipart option)

Multipart Algorithm

  1. Determine optimal chunk count (based on file size and network speed)
  2. Calculate byte ranges for each chunk
  3. Start parallel downloads for each chunk
  4. Aggregate progress from all chunks
  5. Assemble chunks into final file
  6. Verify file integrity

Chunk Management

// Example chunk calculation for 100 MB file with 4 streams
Chunk 0: bytes 0-26214399     (25 MB)
Chunk 1: bytes 26214400-52428799   (25 MB)
Chunk 2: bytes 52428800-78643199   (25 MB)
Chunk 3: bytes 78643200-104857599  (25 MB)
Note: The multipart downloader uses adaptive chunking. It may adjust the number of chunks based on network performance and server response times.

BICURLWrapper

Low-level interface to the system's libcurl library. This component abstracts cURL's C API into a Swift-friendly interface.

Features

  • Direct libcurl integration
  • HTTP/HTTPS support with SSL/TLS
  • Range request support
  • Custom header injection
  • Authentication handling
  • Progress callbacks
  • Timeout management

cURL Configuration

The wrapper configures cURL with optimal settings:

CURLOPT_FOLLOWLOCATION: 1    // Follow redirects
CURLOPT_MAXREDIRS: 10        // Max redirect count
CURLOPT_TIMEOUT: 60          // Connection timeout
CURLOPT_SSL_VERIFYPEER: 1    // Verify SSL certificates
CURLOPT_USERAGENT: "BICurlDownloader/1.0"

Background Audio Components

BIBackgroundAudioManager

Manages background audio playback to keep the app active when backgrounded.

How It Works

  1. Detects when app enters background
  2. Starts silent audio generation
  3. Monitors audio session interruptions
  4. Stops audio when app returns to foreground or all downloads complete

BISilentAudioGenerator

Generates programmatic silent audio using AVAudioEngine.

Technical Details

  • Frequency: ~20 Hz (below human hearing range)
  • Amplitude: Near zero (imperceptible)
  • Format: PCM 16-bit stereo
  • Sample Rate: 44.1 kHz
// Internal audio generation
let format = AVAudioFormat(
    standardFormatWithSampleRate: 44100,
    channels: 2
)
let buffer = generateSilentBuffer(duration: 1.0)
audioEngine.scheduleBuffer(buffer, repeating: true)

BIAudioSessionCoordinator

Coordinates with the app's main audio session to avoid conflicts.

Features

  • Uses AVAudioSessionCategoryOptionMixWithOthers for parallel playback
  • Monitors audio session state changes
  • Handles interruptions (phone calls, alarms)
  • Gracefully deactivates during high-priority audio events

Network Components

BIServerCapabilities

Determines what features the server supports before downloading.

Detected Capabilities

  • Range Requests - Accept-Ranges: bytes
  • Content Length - Total file size
  • Content Type - MIME type
  • ETag - Resource version identifier
  • Last-Modified - File modification date
  • Redirects - Final effective URL

Detection Process

// HEAD request to check capabilities
HEAD /file.zip HTTP/1.1
Host: example.com

// Response
HTTP/1.1 200 OK
Accept-Ranges: bytes
Content-Length: 104857600
Content-Type: application/zip
ETag: "abc123"

BIRangeRequestValidator

Validates that the server correctly implements Range request support.

Validation Tests

  1. Sends test Range request
  2. Verifies 206 Partial Content response
  3. Checks Content-Range header format
  4. Validates byte range accuracy

BINetworkMonitor

Monitors network connectivity and quality using the Network framework.

Monitored Conditions

  • Network availability (connected/disconnected)
  • Connection type (WiFi, Cellular, Wired)
  • Cellular data status
  • Expensive network detection
  • Constrained network detection
// Usage example
let monitor = BINetworkMonitor()
monitor.pathUpdateHandler = { path in
    if path.status == .satisfied {
        if path.usesInterfaceType(.wifi) {
            // WiFi available - start large downloads
        } else if path.usesInterfaceType(.cellular) {
            // Cellular - limit downloads
        }
    }
}

Component Interaction Flow

Download Initiation

User calls manager.download()
    ↓
BIDownloadManager creates BIDownloadTask
    ↓
Task added to queue
    ↓
BIDownloadManager starts task (if slots available)
    ↓
BIDownloadTask checks server capabilities
    ↓
BIServerCapabilities performs HEAD request
    ↓
BIMultipartDownloader created with strategy
    ↓
Download begins using BICURLWrapper
    ↓
Progress updates sent to delegate
    ↓
BIBackgroundAudioManager activated (if needed)
    ↓
Download completes
    ↓
BIFileManager finalizes file
    ↓
Task moves to completed state
    ↓
BIDownloadManager processes queue

Error Handling Flow

Error occurs in BICURLWrapper
    ↓
Error propagated to BIMultipartDownloader
    ↓
BIMultipartDownloader notifies BIDownloadTask
    ↓
Task state changes to failed
    ↓
Delegate receives downloadDidFail
    ↓
BIDownloadManager processes queue
    ↓
Resources cleaned up

Thread Safety

The framework is designed to be thread-safe with proper synchronization:

  • NSLock - Used for protecting critical sections
  • DispatchQueue - Serial queues for ordered operations
  • @MainActor - UI updates always on main thread
  • Atomic Operations - State changes are atomic
Important: Always update UI from the main thread when receiving delegate callbacks. The framework dispatches callbacks on background threads for optimal performance.
