Multipart Download

Accelerate downloads with parallel streams

Overview

Multipart downloading splits a file into multiple chunks and downloads them simultaneously using parallel streams. This can significantly increase download speeds, especially on high-bandwidth connections.

Speed Improvement:
Multipart downloads can be 2-5x faster than single-threaded downloads on high-speed connections, depending on server performance and network conditions.

How It Works

  1. Framework checks if server supports Range requests
  2. File is divided into optimal number of chunks
  3. Each chunk is downloaded in parallel
  4. Progress is aggregated from all chunks
  5. Chunks are assembled into final file

Server Requirements

For multipart downloads to work, the server must support HTTP Range requests.

Required Headers

Header Value Purpose
Accept-Ranges bytes Indicates Range request support
Content-Length File size in bytes Required for chunk calculation
Content-Range bytes 0-1023/2048 Returned with partial content

Server Response Example

// HEAD request to check capabilities
HEAD /file.zip HTTP/1.1
Host: example.com

// Server response
HTTP/1.1 200 OK
Accept-Ranges: bytes
Content-Length: 104857600
Content-Type: application/zip

// Range request
GET /file.zip HTTP/1.1
Host: example.com
Range: bytes=0-26214399

// Server response
HTTP/1.1 206 Partial Content
Content-Range: bytes 0-26214399/104857600
Content-Length: 26214400

Activation Conditions

Multipart download is automatically activated when ALL conditions are met:

Condition Requirement Check Method
Option Enabled enableMultipart = true User configuration
Range Support Server sends Accept-Ranges: bytes HEAD request
Content Length Server provides file size Content-Length header
File Size ≥ 5 MB (5,242,880 bytes) Threshold check
Important: If any condition fails, the framework automatically falls back to single-threaded download without errors.

Chunk Calculation

Algorithm

The framework uses an adaptive algorithm to determine optimal chunk size:

// Simplified chunk calculation
let fileSize: Int64 = 104857600  // 100 MB
let maxStreams = 4
let minChunkSize: Int64 = 1048576  // 1 MB

// Calculate chunk size
let chunkSize = max(fileSize / Int64(maxStreams), minChunkSize)
let actualChunks = Int(ceil(Double(fileSize) / Double(chunkSize)))

// Example for 100 MB file with 4 streams:
// chunkSize = 26,214,400 bytes (25 MB)
// actualChunks = 4

Example Calculations

File Size Streams Chunk Size Actual Chunks
10 MB 4 2.5 MB 4
50 MB 4 12.5 MB 4
100 MB 4 25 MB 4
500 MB 8 62.5 MB 8
1 GB 8 128 MB 8

Byte Range Examples

// For 100 MB file split into 4 chunks:

Chunk 0: Range: bytes=0-26214399 (25 MB)
Chunk 1: Range: bytes=26214400-52428799 (25 MB)
Chunk 2: Range: bytes=52428800-78643199 (25 MB)
Chunk 3: Range: bytes=78643200-104857599 (25 MB + remainder)

Progress Tracking

Progress is aggregated from all parallel streams:

How It Works

// Each chunk reports its progress
Chunk 0: 10 MB / 25 MB = 40%
Chunk 1: 15 MB / 25 MB = 60%
Chunk 2: 8 MB / 25 MB = 32%
Chunk 3: 12 MB / 25 MB = 48%

// Total progress calculation
Total downloaded: 10 + 15 + 8 + 12 = 45 MB
Total size: 100 MB
Overall progress: 45 / 100 = 45%

Implementation Example

// Swift
func downloadDidProgress(_ task: BIDownloadTask, progress: Double) {
    let percentage = Int(progress * 100)
    let bytesDownloaded = task.progress.completedUnitCount
    let totalBytes = task.progress.totalUnitCount
    
    print("Progress: \(percentage)%")
    print("Downloaded: \(bytesDownloaded) / \(totalBytes) bytes")
}

// Objective-C
- (void)downloadDidProgress:(BIDownloadTask *)task progress:(double)progress {
    NSInteger percentage = (NSInteger)(progress * 100);
    int64_t bytesDownloaded = task.progress.completedUnitCount;
    int64_t totalBytes = task.progress.totalUnitCount;
    
    NSLog(@"Progress: %ld%%", (long)percentage);
    NSLog(@"Downloaded: %lld / %lld bytes", bytesDownloaded, totalBytes);
}

File Assembly

Once all chunks complete, the framework assembles them into the final file.

Assembly Process

  1. Wait for all chunks to complete downloading
  2. Verify all chunk files exist
  3. Create output file handle
  4. Sequentially append each chunk in order
  5. Verify final file size matches expected size
  6. Delete temporary chunk files
  7. Notify completion

Temporary Files

// Temporary chunk files during download
/tmp/download_abc123.part0  // Chunk 0
/tmp/download_abc123.part1  // Chunk 1
/tmp/download_abc123.part2  // Chunk 2
/tmp/download_abc123.part3  // Chunk 3

// Final assembled file
/path/to/destination/file.zip

// Chunks are automatically deleted after assembly

Adaptive Configuration Example

import Network

func getOptimalStreamCount(for path: NWPath) -> Int {
    if path.usesInterfaceType(.wifi) {
        return 8  // High-speed WiFi
    } else if path.usesInterfaceType(.cellular) {
        if path.isExpensive {
            return 2  // Cellular data, be conservative
        } else {
            return 4  // Unlimited cellular
        }
    } else {
        return 4  // Default
    }
}

// Usage
let pathMonitor = NWPathMonitor()
pathMonitor.pathUpdateHandler = { path in
    let streamCount = getOptimalStreamCount(for: path)
    
    var options = BIDownloadOptions()
    options.maxConcurrentStreams = streamCount
    
    // Start download with optimized settings
}

Performance Tips

  • File Size - Multipart is most effective for files > 50 MB
  • Server Performance - Fast servers benefit more from multipart
  • Network Quality - High latency reduces multipart effectiveness
  • Stream Count - More streams ≠ always faster (overhead increases)
  • Memory - Each stream uses buffer memory

Error Handling

Chunk Failures

If any chunk fails during download:

  1. Failed chunk is automatically retried
  2. Other chunks continue downloading
  3. After max retries, entire download fails
  4. All temporary files are cleaned up

Recovery Example

// Framework handles chunk failures internally
// Your delegate receives failure only after all retries exhausted

func downloadDidFail(_ task: BIDownloadTask, error: Error) {
    if let nsError = error as NSError? {
        switch nsError.code {
        case BIDownloadErrorCode.networkError.rawValue:
            // Network issue - might retry entire download
            retryDownload(task)
            
        case BIDownloadErrorCode.rangeNotSupported.rawValue:
            // Server doesn't support Range - will use single-threaded
            print("Server doesn't support multipart")
            
        default:
            print("Download failed: \(error)")
        }
    }
}

Limitations

Server Limitations

  • No Range Support - Falls back to single-threaded
  • Connection Limits - Some servers limit concurrent connections per IP
  • Rate Limiting - Server may throttle multiple connections
  • Dynamic Content - Range requests may not work with CDNs

Framework Limitations

  • Min File Size - 5 MB minimum for multipart activation
  • Max Streams - Limited to 16 concurrent streams
  • Memory Usage - Each stream uses buffer memory (~64 KB per stream)
  • Disk I/O - Multiple temporary files created
CDN Considerations: Some CDNs serve different content for Range requests. Always test multipart downloads with your specific server/CDN configuration.

Multipart vs Single-Threaded

Performance Comparison

Aspect Multipart Single-Threaded
Download Speed 2-5x faster (high bandwidth) Baseline
Server Load Higher (multiple connections) Lower
Memory Usage Higher (multiple buffers) Lower
Disk I/O Multiple temp files Single file write
Complexity Higher Lower
Server Requirements Range request support Basic HTTP

When to Use Each

Use Multipart Use Single-Threaded
Large files (>50 MB) Small files (<5 MB)
High-speed connections Slow connections
Static file servers Dynamic content
CDN with Range support Servers without Range support
WiFi connections Metered cellular data

Complete Example

Swift

import BICurlDownloader
import Network

class MultipartDownloadManager {
    let manager = BIDownloadManager.shared
    let pathMonitor = NWPathMonitor()
    var currentPath: NWPath?
    
    init() {
        setupNetworkMonitoring()
    }
    
    func setupNetworkMonitoring() {
        pathMonitor.pathUpdateHandler = { [weak self] path in
            self?.currentPath = path
        }
        pathMonitor.start(queue: DispatchQueue.global())
    }
    
    func downloadWithOptimalSettings(url: URL, destination: String) {
        // Determine optimal stream count based on connection
        let streamCount = getOptimalStreamCount()
        
        // Configure options
        var options = BIDownloadOptions()
        options.enableMultipart = true
        options.maxConcurrentStreams = streamCount
        options.enableBackgroundAudio = true
        
        print("Starting download with \(streamCount) streams")
        
        let task = manager.download(
            url: url,
            destinationPath: destination,
            options: options
        )
        task.delegate = self
    }
    
    func getOptimalStreamCount() -> Int {
        guard let path = currentPath else { return 4 }
        
        if path.usesInterfaceType(.wifi) {
            // High-speed WiFi
            return 8
        } else if path.usesInterfaceType(.cellular) {
            // Cellular - be conservative
            return path.isExpensive ? 2 : 4
        } else {
            return 4
        }
    }
}

extension MultipartDownloadManager: BIDownloadDelegate {
    func downloadDidStart(_ task: BIDownloadTask) {
        print("Download started")
        // Check logs to see if multipart is active
    }
    
    func downloadDidProgress(_ task: BIDownloadTask, progress: Double) {
        let percentage = Int(progress * 100)
        let downloaded = task.progress.completedUnitCount
        let total = task.progress.totalUnitCount
        
        print("Progress: \(percentage)% (\(downloaded) / \(total) bytes)")
    }
    
    func downloadDidComplete(_ task: BIDownloadTask, filePath: String) {
        print("Download completed: \(filePath)")
        
        // Verify file size
        if let attrs = try? FileManager.default.attributesOfItem(atPath: filePath),
           let fileSize = attrs[.size] as? Int64 {
            print("Final file size: \(fileSize) bytes")
        }
    }
    
    func downloadDidFail(_ task: BIDownloadTask, error: Error) {
        print("Download failed: \(error)")
    }
}

Objective-C

@interface MultipartDownloadManager () <BIDownloadDelegate>
@property (nonatomic, strong) BIDownloadManager *manager;
@end

@implementation MultipartDownloadManager

- (instancetype)init {
    self = [super init];
    if (self) {
        _manager = [BIDownloadManager shared];
    }
    return self;
}

- (void)downloadWithOptimalSettingsFromURL:(NSURL *)url destination:(NSString *)destination {
    // Configure options
    BIDownloadOptions *options = [[BIDownloadOptions alloc] init];
    options.enableMultipart = YES;
    options.maxConcurrentStreams = 8;  // High-speed connection
    options.enableBackgroundAudio = YES;
    
    NSLog(@"Starting download with %ld streams", (long)options.maxConcurrentStreams);
    
    BIDownloadTask *task = [self.manager downloadFromURL:url
                                         destinationPath:destination
                                                 options:options];
    task.delegate = self;
}

#pragma mark - BIDownloadDelegate

- (void)downloadDidStart:(BIDownloadTask *)task {
    NSLog(@"Download started");
}

- (void)downloadDidProgress:(BIDownloadTask *)task progress:(double)progress {
    NSInteger percentage = (NSInteger)(progress * 100);
    int64_t downloaded = task.progress.completedUnitCount;
    int64_t total = task.progress.totalUnitCount;
    
    NSLog(@"Progress: %ld%% (%lld / %lld bytes)", (long)percentage, downloaded, total);
}

- (void)downloadDidComplete:(BIDownloadTask *)task filePath:(NSString *)filePath {
    NSLog(@"Download completed: %@", filePath);
    
    // Verify file size
    NSDictionary *attrs = [[NSFileManager defaultManager] attributesOfItemAtPath:filePath error:nil];
    NSNumber *fileSize = attrs[NSFileSize];
    NSLog(@"Final file size: %@ bytes", fileSize);
}

- (void)downloadDidFail:(BIDownloadTask *)task error:(NSError *)error {
    NSLog(@"Download failed: %@", error.localizedDescription);
}

@end
